# Arbor: project notes

- Stack: Vite + TS + three r187; controls panel is own DOM (`src/ui.ts` + `src/ui.css`; lil-gui is still in package.json but unused). Remote `origin` = github.com/trusch/arbor (public); only the coordinator or the user pushes, workers never push. GitHub Pages (https://trusch.github.io/arbor/) serves the `gh-pages` branch, published with `scripts/publish-pages.sh` (clean checkout of a commit; the token has no `workflow` scope, so there is no Actions workflow). On `*.github.io` `public/telemetry.js` sends nothing. Repo has `commit.gpgsign=false` locally.
- All tunables live in `src/params.ts` (`ArborParams`); sim/render read them live. Add new params there and in `src/ui.ts`.
- Sim is three-free (`src/sim/`); renderer reads `TreeNode.w*` (sagged world) fields.
- Children always have larger node ids than parents; `updateStructure` relies on this for its bottom-up and top-down passes.
- Structure pass is incremental (`TreeSim.updateStructure(dt, full = false, defer = false)`, big-tree P1 / P2; `docs/bigtree.md` section 6 has the numbers). The result is bit-equal to recomputing every node (same arithmetic, same summation order: a node's pipe and subtree length are re-summed over its children in descending id order, as the full bottom-up loop adds them). State per node id in typed arrays (`s*` fields: parent, child list, last target `sT`, contribution target^n `sC`, radius copy `sR`, flags). Bottom-up dirty set (`sUp` bit 1): a node whose `len` changed (every alive tip, marked in `step`), a new node and its parent (`addNode`), the nodes of a chain whose `pruned` flag changed and their parents (`sChainDirty`, called by `updateLight` and `shedJuvenile`), and the parent of any node whose contribution or `subLen` came out different; so the set is the growing tips plus their ancestors up to where the sums stop changing. Bit 2 = "radius still below its target": those nodes only get the thickening step from the typed arrays (no node object is read; most wood ends there for good, a few ulp below the target, because the exponential approach stops at the rounding limit; with a longer step it can still move one ulp, so the flag stays). Top-down dirty set (`sDown`): own `len`, `radius` or `subLen` changed, or the parent's sag / position came out different (stamp cascade from the lowest dirty id; a node that comes out the same stops it). While the tree grows the trunk thickens every step, so sag and position of nearly every node do change every step (sub-millimetre): the saving in the growing phase comes from P2, the saving of P1 is the tree at rest (0 nodes recomputed). The bounding box is rescanned over all nodes whenever any node moved. A full pass (`structureFull`, the plain loops, also rebuilds the incremental state) runs: on the first pass after `reset`; after `breakAt` (chain membership and pruned flags of a subtree change); when one of the four values the pass reads changed (`thickness.exponent`, `thickness.twigRadius`, `growth.gravity * growth.sag`, `growth.weeping`; compared by value on every call, so a paused parameter edit needs no version check inside the sim; `thickeningRate` only scales the step); when the node list was replaced behind `addNode`; and on `updateStructure(dt, true)`. `fastForward` needs none (its steps are the same steps). New code that writes `len`, `radius`, `parent`, `node.chain` or `chain.pruned` must mark the nodes (`sChainDirty`, or set `sFull`) or the structure goes stale; `sim.structureCheck()` (debug) runs `updateStructure(0)` incrementally and as a full pass from the same state and returns the largest differences (all 0 = bit-equal), `sim.structStats` counts the last pass (`up`, `thick`, `down`, `moved`, `fullPasses`, `forwardPasses`, `tipPasses`). Forward pass at 10 Hz (P2): inside `step` the bottom-up part (radii, subtree lengths: growth rules read radii) runs every step, the forward part (sag, world positions) every `sim.structureInterval` = 0.1 sim seconds; in between `structureTips` places only the segments that elongated or were created in that step on their parents' last positions and widens the bounding box by them, so a tip moves every frame. Exactness: `step` calls `flushStructure()` before anything elongates when the light tick is due in that step (`updateLight` and `shedJuvenile` then read exactly the positions a per-step pass had left), `loadRatios` flushes first, `updateStructure(...)` called from outside always runs the forward part, and a paused frame flushes (`main.ts`); after a flush the tree is bit-equal to the per-step build. Renderers therefore read positions of non-tip wood that are up to 0.1 sim seconds old (at 1x: 10 Hz steps of the sag settling); a reader that needs exact positions calls `sim.flushStructure()` (no radius change, no-op when current). `?structInterval=0` = forward pass every step. `node scripts/structeq.mjs [oak,oak2x,willow,break]` (REF = git ref of the reference sim) grows the same trees headless with both sims and compares positions, directions, radii, sag, subtree lengths, pruned flags, leaf count and bounding box bit by bit at t = 30 / 90 / 150 (exit 1 on any difference) and prints ms per step; smoke: "structure: incremental pass equals a full recomputation ...".
- Branch mesh chain ranges (big tree P3, `docs/bigtree.md` 6.3): `BranchMesh.update` gives every chain a fixed vertex / index range with 50 % slack and rewrites + uploads only chains whose node inputs (`wx wy wz radius wdx wdy wdz`, exact compare against a per-node copy), ring count or radial count changed; outgrown chains move to the end (old index range degenerate), dense re-layout on waste > 2x, buffer growth, flare change, shrink. Unused index slots are (0,0,0); draw range = all index slots. Anything new the rings read from a node must go into that per-node copy or chains go stale. `applyOffsets` marks the positions swayed and the next update without offsets restores rest. Gates: `scripts/p3check.mjs` (incremental = full in-place rewrite and = fresh mesh, bit by bit), `scripts/p3main.mjs` (drawn-triangle hash across builds). Debris (one update per limb) takes the full-layout path.
- three r187 removed PCFSoftShadowMap; use PCFShadowMap + `shadow.radius`.
- Verify visually: `npm run shots`, then look at the PNGs in `shots/`.
- Look/lighting is driven by `params.sky` (timeOfDay, cycle, dayLength, latitude, sunYaw, exposure, fog, godRays, quality). `params.light` is only the phototropism direction for the sim.
- Preetham sky values blow up bloom at low sun: keep the sky clamp in `atmosphere.ts` (`patchSky`) unless you also retune bloom.
- `scripts/screenshot.mjs` args: stages, extraQuery, prefix, `hour:name,...` list (or `none`). SHOT_W/SHOT_H env set the resolution. Each run takes about 70s on SwiftShader.
- Chains can be `pruned` (shaded out by the light grid in `TreeSim.updateLight`). Renderers must skip pruned chains, and the pipe model ignores them. Radii never shrink.
- Rebuild scheduling (`redraw` in `main.ts`; `redraw(t, 0, true)` forces everything, see `fastForward`). Nothing rebuilds on an unchanged tree. Branch mesh: every frame on High, every second frame on Low, only when `sim.time`, `sim.topology` or `paramsVersion()` moved; it does not trigger a leaf pass. Leaves follow their branches: on every branch rebuild `Leaves.follow(sim, params, cam, LEAF_FOLLOW_MS = 2.5)` re-places the drawn instances on their nodes' current transforms (round-robin chunks of 1024 within the budget, a whole sweep when it fits; ranged `instanceMatrix` uploads of touched chunks only; data-only, no material change). Each sweep starts with `markMoved`: a node counts as moved when its or its parent's position left the reference state by `FOLLOW_EPS` 1.5 mm (direction 0.01, radius 0.2 mm); leaves on nodes at rest are skipped unless still unfolding, which is what lets a sweep of 32k leaves fit about 3 frames at 4x CPU throttle (it took about 21 without the skip). It reads per-instance placement records (`frontD`/`frontNode`: t, cos/sin of around/tilt/roll, base size, born, node id) written by the leaf pass in the order of its colour buffer; records and colours are swapped together when a pass completes (in a frame of its own, not on top of a full slice); instances whose record is unchanged at the same index keep their matrices and only the tail behind the first difference is placed unconditionally (`follow(..., Infinity, from)`), the whole set when the camera moved > 5% of the crown height, the height changed > 3%, or `leaves.shape` / `maxBranchRadius` changed since the last whole placement (those and the distance LOD are not in the records; a new input read by `place` needs the same guard). A pass spans many frames, so it never uploads matrices of its own. `Leaves.place` is the only record-to-matrix code (pass bake and follow share it); unfolding, radius fade and distance LOD are evaluated there with the live sim time and camera. `abortPass` (tree reset) disables follow until the next pass completes. Low: branch rebuild + follow and the pass slice take alternate frames. Leaf pass (instance set, lighting bake, colours): starts only when an input changed: sim time (every 0.12 s, every 0.4 s once topology is stable for 5 s), `sim.lightVersion`, sun direction (2 decimals), `paramsVersion()`, quality, camera distance > 25% or (safe path, its bake is view-dependent) view direction turned > 12°, both ≤ 1/s. The pass is resumable and time-sliced: `Leaves.beginPass` snapshots inputs, `Leaves.stepPass(sim, params, LEAF_BUDGET_MS = 3)` runs each frame into back buffers and swaps them in when the last slice ends (one pass in flight; a dirty flag raised meanwhile starts the next one after it). `Leaves.update` = whole pass in one call. No allocations per leaf (module-level `hr`/`bakeCh`, member quaternions). Leaf mesh is created at final capacity (Low 32k, High 48k; grows only if a pass comes within 10% of it). Paused frames call `sim.updateStructure(0)` only after a params change (otherwise `sim.flushStructure()`, a no-op when positions are current); `regrow` calls `invalidate()`.
- `paramsVersion()` / `bumpParams()` (`params.ts`): bumped by `Automation.userSet`, `setPath` (journey/drift writes of a different value), `loadPreset`, and a per-frame `paramsSignature` check in `frame` that catches direct writes to any group except sky/camera/time. New code that depends on params while paused should compare `paramsVersion()`; a new sky-driven leaf input needs its own dirty term in `redraw`.
- Automation (`src/automation.ts`) writes into the live params object before every sim step; presets are copied into params in place (`loadPreset` in `main.ts`); the panel re-reads params every 400 ms while open. Use `?preset=Name`.
- Sun discs are drawn in the patched sky shader (`disc1*/disc2*` uniforms; its text is frozen, it runs on the phone). Extra sky planes are allowed only the `celestial.ts` way (decal clone + invisible `userData.gbufferMaterial`, otherwise the GTAO override material renders them as solid quads). The env-map sky has `discOn = 0`.
- Screenshot script disables cinema (`cinema=false`) and accepts `PORT` env so several runs can go in parallel (more than ~4 in parallel times out).
- Deploy: `npm run deploy` (build + `systemctl --user restart arbor`). Unit `~/.config/systemd/user/arbor.service` (copy in `deploy/`) runs `server/serve.mjs` on 10.77.0.2:8050 (VPN): static `dist/` + `POST /log` → `logs/client.jsonl`. HTML is served `no-store`. Vite `base: './'`. Ports 8010–8040 belong to other apps.
- `npm run smoke` (scripts/smoke.mjs) drives the app in headless chromium; run it after interaction changes.
- Mobile/low-end (UA mobile, touch + small screen, deviceMemory < 4) defaults to `quality=Low` and `maxNodes ≤ 7000` (`lowEndDevice` in `main.ts`); `?quality=High` overrides. Pixel ratio is adaptive (`Stage.adaptDpr`): starts at min(devicePixelRatio, Low 2 / High 1.5), 3 s windows of rAF intervals (first 3 s, hidden-tab and >2 s-gap windows ignored), decision on the window's median interval so CPU stalls are not taken for GPU load: median > 25 ms steps down 2→1.75→1.5→1.25→1, median < 17.5 ms for 10 s steps up (never above start, blocked 30 s after a step-down); `?dpr=N` pins it; telemetry `dpr_change` {from,to,fps,medianMs} + `pixelRatio` in hb stats. 1024 shadow map on Low (`Stage.applyQuality`). Renderer is antialias:true on every quality (`?antialias=0` diag only). `SHOT_DPR=2.625 node scripts/phoneshots.mjs` emulates the real phone DPR. `Stage.post` is lazy: never touch it on Low or it allocates the GTAO/bloom render targets.
- Context loss shows a notice and reloads on restore; the rAF loop wraps each frame in try/catch (`__arbor.frameErrors()`), so one throw doesn't freeze the app.
- `npm run smoke` also covers reload, junk query values, Android phone emulation and a memory soak (`SOAK_S`, default 120; `SOAK_S=0` skips it).
- SwiftShader runs every page of a headless browser in one GPU process: a page left rendering a grown tree starves the next page (navigations take 60 s+, `page.goto` times out). Close pages you are done with; smoke runs each phone step in a fresh context.
- Telemetry: `public/telemetry.js` (classic, loads before the bundle) + `src/tel.ts` wrapper (`tel.phase`, `tel.log`, `tel.setStats`). Wrap new risky steps in `tel.phase('name')`; per-frame phases pass `frequent=true`. See README "Telemetry and diagnostics".
- Diagnostics switches live in `diagSwitches` (`src/tel.ts`); keep `public/diag.html` links in sync.
- Leaf render modes (`LeafMode` in `src/render/leaves.ts`): 'full' (Standard + onBeforeCompile, DoubleSide, shadows, GPU wind), 'safe' (Lambert, no shader patch, FrontSide doubled geometry, instance colours, no shadows, no wind; geometry/map/vertexColors/emissive per `LEAF_VARIANTS` V0..V4), 'basic' (unlit). Safe is automatic on PowerVR/Imagination, mobile Low and after a context loss in the tab (`pickLeafMode` in `main.ts`); `?leafsafe=1/0`, `?leafshader=basic|safe|full`, `?leafshadow=0/1`. Context losses are counted in `sessionStorage['arbor.ctxLost']`: 1st → reload with safe leaves + no shadows, 2nd → no reload, safe-mode links page. diag.html clears the counter; `/diag` serves it.
- Camera: a view set by hand is the user's until they ask for the automatic camera. Only a real drag (>8 px) or wheel on the canvas calls `stage.takeControl()` (a tap does not; a tap used to freeze the camera at sapling distance). While `stage.manual` is set, nothing automatic writes the camera: cinema, OrbitControls auto-rotate and auto-frame in `Stage.frame` are all gated on it (there is no idle timer; the old 10 s idle resume and the auto-rotate that kept running after release were the "camera resets by itself" bug). `stage.autoCamera()` is the only way back and eases over `EASE_S` 3 s (smoothstep blend from the hand-set pose into the automatic pose, no jump). It is called by: the `#arbor-auto-camera` pill (top left, outside the panel, shown only while `stage.manual`; built in `ui.ts`), the C key (from a hand-set view C returns to the automatic camera with cinema on; otherwise it toggles cinema as before), switching Cinema or Auto-frame from off to on in the More tab, and a new tree (plant new, regrow, preset change). `params.camera.*` are preferences for what the automatic camera does; drags no longer write `autoFrame`. A hand-set view survives the context-loss reload (`arbor.cam` in sessionStorage). New code must not write `camera.position` / `controls.target` outside `Stage.frame`'s `auto` branches. `node scripts/camtrace.mjs [url] [seconds]` logs the pose once a second after a mouse and a touch gesture. Portrait framing fits the crown circle to the horizontal FOV (`Stage.frame`); landscape keeps the sphere fit.
- Director (`src/render/director.ts`, `stage.director`; the cinema branch of `Stage.frame` calls `director.update(...)` and copies `director.pos / tgt` into the camera: still the only camera write, still inside the automatic branch). Active while `params.camera.cinema` and the tree is taller than `DIRECTOR_H` 2.7 m (hysteresis 0.4 m); below that the old cinema code runs unchanged as the seedling shot and calls `director.reset()`; cinema off = the plain auto-frame branch; `stage.intro` is untouched. Camera transforms and one DOM overlay only (`#arbor-cut`, black, `pointer-events: none`, created on the first cut): no material, program, pass or render target, same on Low and High (phone programs 8 in every shot). No depth of field (skipped). A shot is a pure pose function (`pose`) of a smoothed tree box (`H` height, `R` = 0.72 x half the box diagonal in xz + 0.3, `cy`, trunk x/z, `fit` = the framed distance from `Stage.frame`; rate 1.2 /s), the shot clock and values fixed at its start (azimuth `yaw`, `side` +-1, subject point). `aim(pos, point, sx, sy)` turns the view so a world point lands at screen (sx, sy) in -1..1 with a level horizon; thirds and horizon height are set through it, per layout (`P` = aspect < 1). Shots (`SHOT_KINDS`, durations `DUR` x 0.9..1.1): wide (distance `fit`, eye 5 % of it, the horizon point of the trunk at sx 0.36 / sy -0.5, portrait 0.14 / -0.36, 6 % push, 0.008 rad/s drift), hero (distance max(1.95 H, crown width fit), portrait 1.75 H; eye max(1 m, 6.5 % of the distance), portrait 0.7 m: at 0.5 m single grass cards a hand from the lens covered the landscape frame; trunk base at sy -0.7), orbit (0.8 fit, eye 0.3 H, 0.03 rad/s), rise (distance max(2.3 R + 4, H), eye 0.6 m to 0.7 H on a smootherstep, looking 22 % of the distance above its own height, trunk at sx 0.36 / sy -0.2, portrait 0.12: the crown is a shape in the lower third against the sky, not a wall), canopy (2 trunk radii + max(0.7, 0.16 R) from the axis, eye about 1 m, target at 0.74 H just past the axis, 0.022 rad/s), branch (subject = `pickBranch`: outer leafy node near mid crown height on the camera's side; camera 3 to 4.4 m away (0.75 R), 0.55 rad off the radial line, 0.4 x the distance below the subject, subject at sx 0.22 / sy 0.22, 16 % push: the limb is seen against sky and landscape, the crown edge a band at the side); rise and branch stand on the sun's side (sun azimuth + 0.45..0.75 rad) while the sun is above sine 0.08, so the subject is lit (before: half the desktop frame was dark backlit crown mass, `shots/cam-before-{desk,phone}-oak-noon-sheet.jpg` bottom left / right; after `shots/cam-after-*`), plus the event shots storm (wide, lower, more sky) and bird (branch framing at 4.2 m on the perch). Every pose is clamped to `terrainHeight + 0.42` and to 2 trunk radii + 0.45 from the axis. Choice (`choose`): weights x context (low sun: hero, wide; night: wide, hero, few close shots; cloud > 0.6: wide; bloom 0.03..0.14 and autumn 0.5..0.68: branch, canopy, rise; winter: wide; canopy only from 5 m height), never the same twice, own xorshift. Wide, hero and storm take their azimuth from `lightYaw` (camera opposite a sun at sine 0..0.32 or a moon at night, 0.3 rad to one side, so the light is in frame beside the tree); other shots start 0.25 to 0.75 rad from the current azimuth. Transition: the new pose is compared with the current one; nearer than max(8 m, 1.6 H) and under 0.6 rad of view turn and no canopy shot involved = travelling move (`TRAVEL_S` 6 s, smootherstep, azimuth / radius / height blended about the trunk axis so the path cannot cross the crown, target linear; the way round the trunk is chosen in the first travel frame and kept (`travelDy`), so a target azimuth near +-pi cannot flip sides mid-travel); otherwise a dip through black (`CUT_OUT` 0.32 s, pose switches under the opaque overlay in the frame `cutFrame`, `CUT_IN` 0.55 s). Events: `director.event(kind, x, y, z)` from `main.ts` (bird: 2 Hz poll of `critters.state()` for a bird that just perched, at most every 75 s; limb: non-shed break of >= 12 nodes in `breakagePost` = orbit from that side), lightning from `stage.wx.flash` > 0.25, first leaves / blossom / leaf fall from `season.phase` crossing 0.03 / 0.058 / 0.56 from year 2; one pending event, taken only when the running shot is older than `EVENT_MIN_AGE` 7 s and the last event is `EVENT_GAP` 28 s back. User: `director.go(kind?)` = next shot now (N key, `#arbor-next-shot` = a 44 px quiet round button top left, shown only while the director has the camera, i.e. never together with the Auto camera pill; `directorOn` in `main.ts`). Hand-set view: `takeControl` stops everything (the director is simply not called while `stage.manual`); `autoCamera()` calls `director.rest(EASE_S + 6)` so no shot change meets the 3 s ease; cinema switching on resets the director, whose first shot (orbit at the camera's azimuth) travels in from the pose the camera has. Director shots look up from below the target, so `controls.maxPolarAngle` is 0.97 pi while it runs and `takeControl` sets it to max(0.495 pi, the polar angle at the grab) (`grabPolar`, read from the camera pose itself: `getPolarAngle()` is the value of the last `controls.update` and was stale, so the smoke check's scripted low pose was snapped to 0.495 pi before the zoom; `autoCamera` puts the limit back to `grabPolar` for the ease): no snap when the user grabs a low shot. While `manual`, `Stage.frame` limits the hand-set view each frame before `controls.update`: `maxDistance` = max(`HAND_MAX_MIN` 30 m, `HAND_MAX_FIT` 4 x the framed distance) (the zoom-out used to go to 146 m and beyond, the tree a speck), and `maxPolarAngle` = min(`grabPolar`, the polar angle that keeps the eye `HAND_CLEAR` 0.42 m + 3 % of its distance above the terrain under it), so a low grabbed shot zoomed out rises over the rolling terrain beyond 66 m instead of sliding along it; a view at rest gets the same limit it already satisfies (no write); `maxDistance` is Infinity in the automatic modes. Never below the ground in any mode: after `controls.update` `Stage.frame` lifts the camera to `terrainHeight + GROUND_CLEAR` 0.3 m (and re-aims at the target) when it is lower; only an input or an automatic pose can get there, a hand-set view at rest is never touched. OrbitControls damping is per second, not per frame (`dampingFactor = 1 - 0.94^(dt x 60)`): per frame, an 8 fps host glided for over 10 s after a drag, and the smoke check "director never moves a hand-set view" read that glide 2.5 s after release as a camera write (the curve of the pending rotation was the same with and without N / event; nothing automatic writes while `manual`); the check now waits for `camSettled`. `director.state()` = {kind, t, shots, cuts, cutting, travelling, cutFrame}. `PORT=5640 PROF_DIST=dir node scripts/dirshots.mjs [sheet,burst,events,trace] [desk,phone] [prefix]` (CASES=tree:hour,..., TRACE_S). Motion probes time a frame by the rAF timestamp (the frame time the camera moved by): `performance.now()` inside a second rAF callback can sit 2 to 7 ms after the previous one in a 100 ms frame, which turned a 0.1 m step into the "24 m/s, 55 deg/s" frame. Trace after (oak t = 90, noon, 60 s automatic): phone max step 0.10 m, 1.0 m/s, 1.7 deg/s; desktop 0.40 m in a 0.11 s frame, 3.65 m/s, 7.4 deg/s (travel into a bird shot); forced travels every 3.5 s (bird / orbit / hero / rise / branch / wide): phone 2.45 m/s, 3.9 deg/s, desktop 2.75 m/s, 2.5 deg/s. Smoke: "director cycles through distinct shots ... tree partly in frame in every shot" (crown centre, trunk at H / 3 or a crown box corner on screen in every non-cut frame), "director never moves a hand-set view ...", "hand-set zoom-out from a low director shot stays above the terrain"; "auto-frame (cinema off) keeps crown bbox in view" tests the plain framed view (director shots crop the crown by design). Open: on desktop High the branch shot is still about half crown (now lit, with sky through it); the branch subject is a node, not a composed cluster; bird and limb shots do not check that the subject is unobstructed; no shot was tuned for presets other than the oak; events for first leaves / blossom / autumn were not run; a travel started while the tree grows fast blends from a frozen pose.
- Low quality: tight light-space shadow frustum + larger bias, warm bark tint (main.ts). High keeps the old values.
- Debug HUD line is hidden by default: `?hud=1` or D. `node scripts/phoneshots.mjs [stages] [query] [prefix]` renders Android-emulated 411x777 framed + trunk close-up shots.
- Leaf variants (`LEAF_VARIANTS` in `src/render/leaves.ts`): V0 = 1d88059 known-good (doubled card + uv + leaf map + alphaTest 0.5, no vertexColors, emissive black) is the hard-pinned default for every safe/basic leaf path (PowerVR/Imagination, mobile Low, after a context loss). V4 (polygon, vertexColors+emissive, no map/uv) killed the PowerVR D-Series context on the first leaf frame. `?leafvariant=N` is a manual dev override only (diag.html warns V1–V4 may crash the GPU). There is no automatic BAD marking and no on-device variant ladder: a crashing variant resets the GPU for all tabs and Chrome then blocks WebGL for the site; a background tab's context loss falsely marked V0 bad. `main.ts` deletes stale `localStorage['arbor.leafBad.*']` / `arbor.ladder` keys on load. `node scripts/leafvariants.mjs '' leafvariant=0 ...` renders variants in headless phone emulation (404s are POST /log on vite: ignore).
- Context losses while `document.visibilityState === 'hidden'` are logged (`ctx_loss_hidden`) but do not count toward the crash guard or change modes; the page reloads as-is once visible after restore (`Stage` constructor).
- WebGL renderer creation failure (Chrome blocks WebGL after a GPU reset) shows a full-page "3D graphics are blocked" message (`#nowebgl`, telemetry `webgl_create_failed`) and stops `main.ts` via a never-resolving top-level await.
- Safe leaf map is `cleanLeafTexture` (alpha exactly 0/1, RGB dilated with the leaf colour, hand-built mips re-thresholded at 0.5): the premultiplied canvas map had black RGB under transparency and GPU mips whose alpha averaged to ~0.5 over the card. `?leafmap=raw` restores the old map for comparison. Ghost cards did not reproduce on SwiftShader with either map. Renderer is explicitly `alpha: false`.
- Leaf lighting is CPU-baked into instance colours (`Leaves.update`, inputs via `Leaves.setLighting` from `main.ts` each leaf rebuild). Safe path: colour = albedo/mapMean × E_wanted/E_lambert per channel (E_wanted = hemi·occlusion + sun·|n·L|·sunVis + translucency glow when the sun is behind the leaf from the camera; E_lambert = what the Lambert shader will add), clamped to 8. Full path bakes only albedo × occlusion (its shader does sun/shadow/translucency). Sun visibility = per-voxel march through `TreeSim.lightGrid` (stored by `updateLight`, `lightVersion` bumps) toward the sun. Light grid (big tree P5): cell = max(4 x `segmentLength`, tree height / `LIGHT_CELLS_H` 28), i.e. the old 0.88 m for every tree up to about 24.6 m (default oak, `?years=3` at 15 m and oak2x keep the same grid, bit-equal); node light is evaluated once per occupied cell (same expression, bit-equal: `structeq.mjs` oak, oak2x, willow, break against the build before).
- Leaves come in 8-leaf clumps per leafy node: 4 from the sim rng + 4 smaller tip leaves from a per-node hash (does not consume the sim rng: tree shapes are unchanged). Oak default size 0.145, density 3.4. Render-side shell fill: each sim leaf on a lit node (`nd.light` 0.06→0.4) gets up to one hashed extra copy (≈ 8 → 13 per outer clump, interior stays sparse); leaves scale up to 1.5x with camera distance (0.9H→2.6H, H = crown height) so the far silhouette fills; `main.ts` rebakes when the camera distance changes > 25% (≤ 1/s). Low caps drawn leaves at 32k (`Leaves.maxInstances`, rank thinning); oak at t90 ≈ 30k phone / 33.6k desktop. No leaves on segments pointing steeply down (`wdy < -0.75`).
- Leaf map: `makeLeafTexture(form)` (textures.ts; forms below) paints the oak as a 512 px leaf procedurally (lobed asymmetric outline + teeth, base→tip gradient, tapering lighter veins, blotches/speckles, dark margin, baked sheen) in real albedo colours; instance colours divide by its mean (`mapMeanColor`), so retuning colours does not shift the lighting bake. Safe path still goes through `cleanLeafTexture`.
- Canopy shadow (`src/render/canopyShadow.ts`): whenever leaves don't cast shadow-map shadows (safe path), a CPU-baked 256² canvas is drawn as a transparent MeshBasicMaterial ground plane, and branches stop casting. The bake is deposit-then-blur in a sun-aligned frame (texture u = sun azimuth, w = perpendicular, independent texel sizes; the plane is rotated about y to the azimuth and scaled to the footprint): each leafy node and each sample along order ≤ 1 limbs is projected along the sun and deposited bilinearly into two of 5 blur-level layers on a 128² blur grid picked by its penumbra sigma (own radius + 0.035 × height / sun elevation), then the layers are cascaded widest-first with one fractional-box sliding pass per axis and level (sigma × stretch along u) and upsampled to 256², followed by the trunk contact ring, elliptical sun flecks, world-anchored dapple noise and the opacity map (0.3 low sun → 0.55 noon). Cost is a fixed 10 passes over 128² plus one opacity pass over 256², independent of sun height (do not go back to per-caster gaussian splats: that was 700 ms at 4x throttle). `canopy.lastMs/maxMs/bakes` hold bake timings. Rebuilds when the sun moves or the light grid changes (≥ 2 s while growing; see "Ground shadow glides with the sun" for the per-frame plane and the opacity); before the first light grid exists (seedling, about the first 13 s) the node count stands in for the light version, so the plant has a shadow from the first second. A bake never shows as a step ("the shadow jumps while growing"; before: no decal until t = 12 to 15 s, then every bake refitted plane and texel grid to the footprint, position steps up to 1.2 m and scale steps up to 3.5 m at 1x, flecks placed in texture space so each one landed somewhere else, 6 to 27 of 255 alpha in one frame at a fixed ground point on every bake). Three rules: (1) the grid is world-anchored: the blur cell size per axis comes from a ladder (steps of 2^(1/3), footprint / (N - 2) rounded up) and the origin sits on a multiple of the cell, so a growing footprint adds whole cells and unchanged content keeps its texels until the ladder steps (texels are up to 26 % coarser than a tight fit); (2) sun-fleck candidates are one hashed fleck per cell of a 0.5 m lattice in world x/z (not `fr() * S` in the texture); (3) cross-fade on the CPU, same plane, material and texture: the bake writes its alpha to `to`, the alpha drawn now (`shown`) is resampled bilinearly into the new frame as `from` (exact while the grid only shifted by whole texels; also covers a ladder step and a turned sun), and `fadeTo` blends `from` to `to` in `fadeN` uploads of `FADE_S / FADE_STEPS` 0.075 s each, `fadeN` = ceil(largest |to - from| of the bake / `FADE_MAX_STEP` 5) clamped to 6..`FADE_STEPS_MAX` 16 (0.45 to 1.2 s, under the 1.5 s / 2 s bake gaps; a bake meeting a running fade starts from what is drawn). Fixed 6 steps gave the smoke probe 8.2 to 12.2 of 255 per frame: the seedling bake around t = 9 changes a point by up to about 48 in 2 s of growth, and how much depends on where the bake lands on the texel ladder (4 to 8 in the same probe, 60 fps, no skipped fade steps; clouds, meadow and light do not enter, the probe reads the decal texture's alpha). - Ground shadow glides with the sun ("the big shadow moves in jumps"). (1) `CanopyShadow.follow(dir)` runs every frame in `redraw`: the texture is a projection along the light, a caster at height y lands y x slope along the azimuth, so the drawn plane is turned about the trunk base to this frame's azimuth and stretched along it by slope / baked slope (`kOf`, clamped 0.4..2.5; exact on the trunk axis, off by horizontal offset x (turn + stretch since the bake) elsewhere, which the next cross-fade removes). A pure function of the frame's light and the bake record (`fr`). The cross-fade resamples the old frame where it is drawn now (both frames share the azimuth of the frame, so the resample is axis-aligned). - Wind sway (`src/render/sway.ts`, no three import; `sway` in `main.ts`, `params.sway.amount`, Sky tab "Branch sway", `?sway=0`). The deflection limit acts on the whole shoot: `cap = TH_MAX / sqrt(1 + (TH_MAX · L / D_LIM)²)` (`TH_MAX` 0.63, `D_LIM` 2 m), L = flex-weighted length (metres x flex / `FLEX_MAX`, so a trunk counts for almost nothing) of the longest path root → node → tip, cached with the rest data (one reverse and one forward loop over typed arrays); L is the same all along a path and smaller on side shoots, so the cap never decreases toward a tip and a long whip bends less per metre from base to tip.
