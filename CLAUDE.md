# Arbor: project notes

- Stack: Vite + TS + three r187; controls panel is own DOM (`src/ui.ts` + `src/ui.css`; lil-gui is still in package.json but unused). Local git only, no remote. Repo has `commit.gpgsign=false` locally.
- All tunables live in `src/params.ts` (`ArborParams`); sim/render read them live. Add new params there and in `src/ui.ts`.
- Sim is three-free (`src/sim/`); renderer reads `TreeNode.w*` (sagged world) fields.
- Children always have larger node ids than parents; `updateStructure` relies on this for its bottom-up and top-down passes.
- three r187 removed PCFSoftShadowMap; use PCFShadowMap + `shadow.radius`.
- Verify visually: `npm run shots`, then look at the PNGs in `shots/`.
- Look/lighting is driven by `params.sky` (timeOfDay, cycle, dayLength, latitude, sunYaw, exposure, fog, godRays, quality). `params.light` is only the phototropism direction for the sim.
- Preetham sky values blow up bloom at low sun: keep the sky clamp in `atmosphere.ts` (`patchSky`) unless you also retune bloom.
- `scripts/screenshot.mjs` args: stages, extraQuery, prefix, `hour:name,...` list (or `none`). SHOT_W/SHOT_H env set the resolution. Each run takes about 70s on SwiftShader.
- Chains can be `pruned` (shaded out by the light grid in `TreeSim.updateLight`). Renderers must skip pruned chains, and the pipe model ignores them. Radii never shrink.
- Rebuild scheduling (`redraw` in `main.ts`; `redraw(t, 0, true)` forces everything, see `fastForward`). Nothing rebuilds on an unchanged tree. Branch mesh: every frame on High, every second frame on Low, only when `sim.time`, `sim.topology` or `paramsVersion()` moved; it does not trigger a leaf pass. Leaves follow their branches: on every branch rebuild `Leaves.follow(sim, params, cam, LEAF_FOLLOW_MS = 2.5)` re-places the drawn instances on their nodes' current transforms (round-robin chunks of 1024 within the budget, a whole sweep when it fits; ranged `instanceMatrix` uploads; data-only, no material change). It reads per-instance placement records (`frontD`/`frontNode`: t, cos/sin of around/tilt/roll, base size, born, node id) written by the leaf pass in the order of its colour buffer; records and colours are swapped together when a pass completes, followed by one full `follow` (a pass spans many frames, so it never uploads matrices of its own). `Leaves.place` is the only record-to-matrix code (pass bake and follow share it); unfolding, radius fade and distance LOD are evaluated there with the live sim time and camera. `abortPass` (tree reset) disables follow until the next pass completes. Low: branch rebuild + follow and the pass slice take alternate frames. Leaf pass (instance set, lighting bake, colours): starts only when an input changed: sim time (every 0.12 s, every 0.4 s once topology is stable for 5 s), `sim.lightVersion`, sun direction (2 decimals), `paramsVersion()`, quality, camera distance > 25% or (safe path, its bake is view-dependent) view direction turned > 12°, both ≤ 1/s. The pass is resumable and time-sliced: `Leaves.beginPass` snapshots inputs, `Leaves.stepPass(sim, params, LEAF_BUDGET_MS = 3)` runs each frame into back buffers and swaps them in when the last slice ends (one pass in flight; a dirty flag raised meanwhile starts the next one after it). `Leaves.update` = whole pass in one call. No allocations per leaf (module-level `hr`/`bakeCh`, member quaternions). Leaf mesh is created at final capacity (Low 32k, High 48k; grows only if a pass comes within 10% of it). Paused frames call `sim.updateStructure(0)` only after a params change; `regrow` calls `invalidate()`.
- `paramsVersion()` / `bumpParams()` (`params.ts`): bumped by `Automation.userSet`, `setPath` (journey/drift writes of a different value), `loadPreset`, and a per-frame `paramsSignature` check in `frame` that catches direct writes to any group except sky/camera/time. New code that depends on params while paused should compare `paramsVersion()`; a new sky-driven leaf input needs its own dirty term in `redraw`.
- Automation (`src/automation.ts`) writes into the live params object before every sim step; presets are copied into params in place (`loadPreset` in `main.ts`); the panel re-reads params every 400 ms while open. Use `?preset=Name`.
- Sun discs are drawn in the patched sky shader (`disc1*/disc2*` uniforms); do not use sprites (GTAO override material renders them as solid quads). The env-map sky has `discOn = 0`.
- Screenshot script disables cinema (`cinema=false`) and accepts `PORT` env so several runs can go in parallel (more than ~4 in parallel times out).
- Deploy: `npm run deploy` (build + `systemctl --user restart arbor`). Unit `~/.config/systemd/user/arbor.service` (copy in `deploy/`) runs `server/serve.mjs` on 10.77.0.2:8050 (VPN): static `dist/` + `POST /log` → `logs/client.jsonl`. HTML is served `no-store`. Vite `base: './'`. Ports 8010–8040 belong to other apps.
- `npm run smoke` (scripts/smoke.mjs) drives the app in headless chromium; run it after interaction changes.
- Mobile/low-end (UA mobile, touch + small screen, deviceMemory < 4) defaults to `quality=Low` and `maxNodes ≤ 7000` (`lowEndDevice` in `main.ts`); `?quality=High` overrides. Pixel ratio is adaptive (`Stage.adaptDpr`): starts at min(devicePixelRatio, Low 2 / High 1.5), 3 s windows of rAF intervals (first 3 s, hidden-tab and >2 s-gap windows ignored), decision on the window's median interval so CPU stalls are not taken for GPU load: median > 25 ms steps down 2→1.75→1.5→1.25→1, median < 17.5 ms for 10 s steps up (never above start, blocked 30 s after a step-down); `?dpr=N` pins it; telemetry `dpr_change` {from,to,fps,medianMs} + `pixelRatio` in hb stats. 1024 shadow map on Low (`Stage.applyQuality`). Renderer is antialias:true on every quality (`?antialias=0` diag only). `SHOT_DPR=2.625 node scripts/phoneshots.mjs` emulates the real phone DPR. `Stage.post` is lazy: never touch it on Low or it allocates the GTAO/bloom render targets.
- Context loss shows a notice and reloads on restore; the rAF loop wraps each frame in try/catch (`__arbor.frameErrors()`), so one throw doesn't freeze the app.
- `npm run smoke` also covers reload, junk query values, Android phone emulation and a memory soak (`SOAK_S`, default 120; `SOAK_S=0` skips it).
- SwiftShader runs every page of a headless browser in one GPU process: a page left rendering a grown tree starves the next page (navigations take 60 s+, `page.goto` times out). Close pages you are done with; smoke runs each phone step in a fresh context.
- Telemetry: `public/telemetry.js` (classic, loads before the bundle) + `src/tel.ts` wrapper (`tel.phase`, `tel.log`, `tel.setStats`). Wrap new risky steps in `tel.phase('name')`; per-frame phases pass `frequent=true`. See README "Telemetry and diagnostics".
- Diagnostics switches live in `diagSwitches` (`src/tel.ts`); keep `public/diag.html` links in sync.
- Leaf render modes (`LeafMode` in `src/render/leaves.ts`): 'full' (Standard + onBeforeCompile, DoubleSide, shadows, GPU wind), 'safe' (Lambert, no shader patch, FrontSide doubled geometry, instance colours, no shadows, no wind; geometry/map/vertexColors/emissive per `LEAF_VARIANTS` V0..V4), 'basic' (unlit). Safe is automatic on PowerVR/Imagination, mobile Low and after a context loss in the tab (`pickLeafMode` in `main.ts`); `?leafsafe=1/0`, `?leafshader=basic|safe|full`, `?leafshadow=0/1`. Context losses are counted in `sessionStorage['arbor.ctxLost']`: 1st → reload with safe leaves + no shadows, 2nd → no reload, safe-mode links page. diag.html clears the counter; `/diag` serves it.
- Camera: only a real drag (>8 px) or wheel disables autoFrame (a tap used to freeze the camera at sapling distance). Portrait framing fits the crown circle to the horizontal FOV (`Stage.frame`); landscape keeps the sphere fit.
- Low quality: tight light-space shadow frustum + larger bias, warm bark tint (main.ts). High keeps the old values.
- Debug HUD line is hidden by default: `?hud=1` or D. `node scripts/phoneshots.mjs [stages] [query] [prefix]` renders Android-emulated 411x777 framed + trunk close-up shots.
- Leaf variants (`LEAF_VARIANTS` in `src/render/leaves.ts`): V0 = 1d88059 known-good (doubled card + uv + leaf map + alphaTest 0.5, no vertexColors, emissive black) is the hard-pinned default for every safe/basic leaf path (PowerVR/Imagination, mobile Low, after a context loss). V4 (polygon, vertexColors+emissive, no map/uv) killed the PowerVR D-Series context on the first leaf frame. `?leafvariant=N` is a manual dev override only (diag.html warns V1–V4 may crash the GPU). There is no automatic BAD marking and no on-device variant ladder: a crashing variant resets the GPU for all tabs and Chrome then blocks WebGL for the site; a background tab's context loss falsely marked V0 bad. `main.ts` deletes stale `localStorage['arbor.leafBad.*']` / `arbor.ladder` keys on load. `node scripts/leafvariants.mjs '' leafvariant=0 ...` renders variants in headless phone emulation (404s are POST /log on vite: ignore).
- Context losses while `document.visibilityState === 'hidden'` are logged (`ctx_loss_hidden`) but do not count toward the crash guard or change modes; the page reloads as-is once visible after restore (`Stage` constructor).
- WebGL renderer creation failure (Chrome blocks WebGL after a GPU reset) shows a full-page "3D graphics are blocked" message (`#nowebgl`, telemetry `webgl_create_failed`) and stops `main.ts` via a never-resolving top-level await.
- Safe leaf map is `cleanLeafTexture` (alpha exactly 0/1, RGB dilated with the leaf colour, hand-built mips re-thresholded at 0.5): the premultiplied canvas map had black RGB under transparency and GPU mips whose alpha averaged to ~0.5 over the card. `?leafmap=raw` restores the old map for comparison. Ghost cards did not reproduce on SwiftShader with either map. Renderer is explicitly `alpha: false`.
- Leaf lighting is CPU-baked into instance colours (`Leaves.update`, inputs via `Leaves.setLighting` from `main.ts` each leaf rebuild). Safe path: colour = albedo/mapMean × E_wanted/E_lambert per channel (E_wanted = hemi·occlusion + sun·|n·L|·sunVis + translucency glow when the sun is behind the leaf from the camera; E_lambert = what the Lambert shader will add), clamped to 8. Full path bakes only albedo × occlusion (its shader does sun/shadow/translucency). Sun visibility = per-voxel march through `TreeSim.lightGrid` (stored by `updateLight`, `lightVersion` bumps) toward the sun.
- Leaves come in 8-leaf clumps per leafy node: 4 from the sim rng + 4 smaller tip leaves from a per-node hash (does not consume the sim rng: tree shapes are unchanged). Oak default size 0.145, density 3.4. Render-side shell fill: each sim leaf on a lit node (`nd.light` 0.06→0.4) gets up to one hashed extra copy (≈ 8 → 13 per outer clump, interior stays sparse); leaves scale up to 1.5x with camera distance (0.9H→2.6H, H = crown height) so the far silhouette fills; `main.ts` rebakes when the camera distance changes > 25% (≤ 1/s). Low caps drawn leaves at 32k (`Leaves.maxInstances`, rank thinning); oak at t90 ≈ 30k phone / 33.6k desktop. No leaves on segments pointing steeply down (`wdy < -0.75`).
- Leaf map: `makeLeafTexture` (textures.ts) paints a 512 px oak leaf procedurally (lobed asymmetric outline + teeth, base→tip gradient, tapering lighter veins, blotches/speckles, dark margin, baked sheen) in real albedo colours; instance colours divide by its mean (`mapMeanColor`), so retuning colours does not shift the lighting bake. Safe path still goes through `cleanLeafTexture`.
- Canopy shadow (`src/render/canopyShadow.ts`): whenever leaves don't cast shadow-map shadows (safe path), a CPU-baked 256² canvas is drawn as a transparent MeshBasicMaterial ground plane, and branches stop casting. The bake is deposit-then-blur in a sun-aligned frame (texture u = sun azimuth, w = perpendicular, independent texel sizes; the plane is rotated about y to the azimuth and scaled to the footprint): each leafy node and each sample along order ≤ 1 limbs is projected along the sun and deposited bilinearly into two of 5 blur-level layers on a 128² blur grid picked by its penumbra sigma (own radius + 0.035 × height / sun elevation), then the layers are cascaded widest-first with one fractional-box sliding pass per axis and level (sigma × stretch along u) and upsampled to 256², followed by the trunk contact ring, elliptical sun flecks, world-anchored dapple noise and the opacity map (0.3 low sun → 0.55 noon). Cost is a fixed 10 passes over 128² plus one opacity pass over 256², independent of sun height (do not go back to per-caster gaussian splats: that was 700 ms at 4x throttle). `canopy.lastMs/maxMs/bakes` hold bake timings. Rebuilds when the sun moves or the light grid changes (≥ 2 s while growing). PowerVR rule: safe-path changes stay data-only (instance colours/matrices, texture pixels, plane transform, intensities, castShadow); no new leaf material flags/programs.
- GTAO renders its normal/depth g-buffer with `scene.overrideMaterial` (no map/alphaTest). Alpha-cut objects must set `userData.gbufferMaterial` (allowOverride=false), which `Post` swaps in for that pass. Leaves do this; otherwise whole quads show up close. `node scripts/closeup.mjs [prefix] [hours] [query] [dist]` takes close-up crown shots (NOAO=1 turns GTAO off).
- Controls panel rules: every control writes through `Automation.userSet(path, value)` (hand-set value wins: path leaves all journey keyframes, its drift goes off). Never write `params.x = v` from UI code for automatable params, or a journey/drift overwrites it on the next sim step (that was the "values reset" bug). Controls are declared as data (`TREE`, `SKY`, `ADVANCED` in `ui.ts`); add a section with one `tab(...)` call. Stable hooks for scripts: `[data-tab]`, `.ap-chip[data-preset]`, `input[data-param="group.field"]`, `[data-drift]`, `[data-colour]`, `#arbor-panel(-open|-close)`, `#arbor-pause`, `#arbor-new`, `#arbor-regrow`, `#arbor-surprise`, `#arbor-add-keyframe`, `#arbor-clear-journey`, `#arbor-journey-info`. `?panel=open|closed`, `?tab=`. No `backdrop-filter` on the panel (blurring the canvas costs the phone GPU). H/C/D work while a slider, switch or button has focus (`typing()` in `main.ts`).
- Smoke on a vite dev server fails its console-error checks (POST /log 404s). Run it against the built app: `npm run build && HOST=127.0.0.1 PORT=5301 node server/serve.mjs`, then `SOAK_S=0 node scripts/smoke.mjs http://127.0.0.1:5301/`. `PORT=5300 node scripts/panelshots.mjs` takes the panel screenshots.
- Meadow (`src/render/meadow.ts`, WP3): grass tufts + 4 wildflower species as 32 `InstancedMesh` patches (24 grass wind-phase patches, 2 per flower species) inside one `Group` (`main.ts` sweeps the scene's direct InstancedMesh children on leaf realloc, so never add them to the scene directly). PowerVR rule: each material is `leafMaterial.clone()` with only `map` swapped (maps through `cleanLeafTexture`), geometry = 3 crossed doubled cards with position/normal(up)/uv, instanceColor, no shadows; smoke asserts the phone program count equals `?meadow=0` at noon and night (9). Motion = per-patch shear object matrix from `wind.gustAlong(phase)` each frame, zero buffer uploads. Instance matrices/colours are rebaked 2 patches per frame when the sun key, night, tint, trunk radius, draw fraction or (≤ every 3 s) the light grid changes: shade = march through `sim.lightGrid` (up = shorter/sparser plants, toward the sun = darker), colour gains are tuned against the ground in screenshots, low sun adds an upright-blade term. 20k tufts / 2600 flowers generated; Low draws 30 % (6k / 784), 15 % once the adaptive pixel ratio stepped below 1.5. Patches are assigned by distance along the wind at construction: changing `wind.dirX/dirZ` later needs a re-sort. `?meadow=0`, `params.sky.meadow`, `__arbor.meadow.counts/stats`. On High each mesh has a `userData.gbufferMaterial` for GTAO. `node scripts/meadowshots.mjs [hour]` = trunk-base shot + 0.5 s motion diff; `SHOT_PREFIX` env on `auditshots.mjs`.
- Wind (`src/wind.ts`, no three import): the single wind source, `wind.update(dt, params.sky.wind, night)` once per frame in `main.ts` (`meadowFrame`), `wind.gust(x, z)` / `gustAlong(d)` travelling wave. Later packages (leaf wind, falling leaves, storms) read this, never their own clock.
