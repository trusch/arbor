# Arbor: project notes

- Stack: Vite + TS + three r187; controls panel is own DOM (`src/ui.ts` + `src/ui.css`; lil-gui is still in package.json but unused). Local git only, no remote. Repo has `commit.gpgsign=false` locally.
- All tunables live in `src/params.ts` (`ArborParams`); sim/render read them live. Add new params there and in `src/ui.ts`.
- Sim is three-free (`src/sim/`); renderer reads `TreeNode.w*` (sagged world) fields.
- Children always have larger node ids than parents; `updateStructure` relies on this for its bottom-up and top-down passes.
- three r187 removed PCFSoftShadowMap; use PCFShadowMap + `shadow.radius`.
- Verify visually: `npm run shots`, then look at the PNGs in `shots/`.
- Look/lighting is driven by `params.sky` (timeOfDay, cycle, dayLength, latitude, sunYaw, exposure, fog, godRays, quality). `params.light` is only the phototropism direction for the sim.
- Preetham sky values blow up bloom at low sun: keep the sky clamp in `atmosphere.ts` (`patchSky`) unless you also retune bloom.
- `scripts/screenshot.mjs` args: stages, extraQuery, prefix, `hour:name,...` list (or `none`). SHOT_W/SHOT_H env set the resolution. Each run takes about 70s on SwiftShader.
- Chains can be `pruned` (shaded out by the light grid in `TreeSim.updateLight`). Renderers must skip pruned chains, and the pipe model ignores them. Radii never shrink.
- Rebuild scheduling (`redraw` in `main.ts`; `redraw(t, 0, true)` forces everything, see `fastForward`). Nothing rebuilds on an unchanged tree. Branch mesh: every frame on High, every second frame on Low, only when `sim.time`, `sim.topology` or `paramsVersion()` moved; it does not trigger a leaf pass. Leaves follow their branches: on every branch rebuild `Leaves.follow(sim, params, cam, LEAF_FOLLOW_MS = 2.5)` re-places the drawn instances on their nodes' current transforms (round-robin chunks of 1024 within the budget, a whole sweep when it fits; ranged `instanceMatrix` uploads of touched chunks only; data-only, no material change). Each sweep starts with `markMoved`: a node counts as moved when its or its parent's position left the reference state by `FOLLOW_EPS` 1.5 mm (direction 0.01, radius 0.2 mm); leaves on nodes at rest are skipped unless still unfolding, which is what lets a sweep of 32k leaves fit about 3 frames at 4x CPU throttle (it took about 21 without the skip). It reads per-instance placement records (`frontD`/`frontNode`: t, cos/sin of around/tilt/roll, base size, born, node id) written by the leaf pass in the order of its colour buffer; records and colours are swapped together when a pass completes (in a frame of its own, not on top of a full slice); instances whose record is unchanged at the same index keep their matrices and only the tail behind the first difference is placed unconditionally (`follow(..., Infinity, from)`), the whole set when the camera moved > 5% of the crown height, the height changed > 3%, or `leaves.shape` / `maxBranchRadius` changed since the last whole placement (those and the distance LOD are not in the records; a new input read by `place` needs the same guard). A pass spans many frames, so it never uploads matrices of its own. `Leaves.place` is the only record-to-matrix code (pass bake and follow share it); unfolding, radius fade and distance LOD are evaluated there with the live sim time and camera. `abortPass` (tree reset) disables follow until the next pass completes. Low: branch rebuild + follow and the pass slice take alternate frames. Leaf pass (instance set, lighting bake, colours): starts only when an input changed: sim time (every 0.12 s, every 0.4 s once topology is stable for 5 s), `sim.lightVersion`, sun direction (2 decimals), `paramsVersion()`, quality, camera distance > 25% or (safe path, its bake is view-dependent) view direction turned > 12°, both ≤ 1/s. The pass is resumable and time-sliced: `Leaves.beginPass` snapshots inputs, `Leaves.stepPass(sim, params, LEAF_BUDGET_MS = 3)` runs each frame into back buffers and swaps them in when the last slice ends (one pass in flight; a dirty flag raised meanwhile starts the next one after it). `Leaves.update` = whole pass in one call. No allocations per leaf (module-level `hr`/`bakeCh`, member quaternions). Leaf mesh is created at final capacity (Low 32k, High 48k; grows only if a pass comes within 10% of it). Paused frames call `sim.updateStructure(0)` only after a params change; `regrow` calls `invalidate()`.
- `paramsVersion()` / `bumpParams()` (`params.ts`): bumped by `Automation.userSet`, `setPath` (journey/drift writes of a different value), `loadPreset`, and a per-frame `paramsSignature` check in `frame` that catches direct writes to any group except sky/camera/time. New code that depends on params while paused should compare `paramsVersion()`; a new sky-driven leaf input needs its own dirty term in `redraw`.
- Automation (`src/automation.ts`) writes into the live params object before every sim step; presets are copied into params in place (`loadPreset` in `main.ts`); the panel re-reads params every 400 ms while open. Use `?preset=Name`.
- Sun discs are drawn in the patched sky shader (`disc1*/disc2*` uniforms); do not use sprites (GTAO override material renders them as solid quads). The env-map sky has `discOn = 0`.
- Screenshot script disables cinema (`cinema=false`) and accepts `PORT` env so several runs can go in parallel (more than ~4 in parallel times out).
- Deploy: `npm run deploy` (build + `systemctl --user restart arbor`). Unit `~/.config/systemd/user/arbor.service` (copy in `deploy/`) runs `server/serve.mjs` on 10.77.0.2:8050 (VPN): static `dist/` + `POST /log` → `logs/client.jsonl`. HTML is served `no-store`. Vite `base: './'`. Ports 8010–8040 belong to other apps.
- `npm run smoke` (scripts/smoke.mjs) drives the app in headless chromium; run it after interaction changes.
- Mobile/low-end (UA mobile, touch + small screen, deviceMemory < 4) defaults to `quality=Low` and `maxNodes ≤ 7000` (`lowEndDevice` in `main.ts`); `?quality=High` overrides. Pixel ratio is adaptive (`Stage.adaptDpr`): starts at min(devicePixelRatio, Low 2 / High 1.5), 3 s windows of rAF intervals (first 3 s, hidden-tab and >2 s-gap windows ignored), decision on the window's median interval so CPU stalls are not taken for GPU load: median > 25 ms steps down 2→1.75→1.5→1.25→1, median < 17.5 ms for 10 s steps up (never above start, blocked 30 s after a step-down); `?dpr=N` pins it; telemetry `dpr_change` {from,to,fps,medianMs} + `pixelRatio` in hb stats. 1024 shadow map on Low (`Stage.applyQuality`). Renderer is antialias:true on every quality (`?antialias=0` diag only). `SHOT_DPR=2.625 node scripts/phoneshots.mjs` emulates the real phone DPR. `Stage.post` is lazy: never touch it on Low or it allocates the GTAO/bloom render targets.
- Context loss shows a notice and reloads on restore; the rAF loop wraps each frame in try/catch (`__arbor.frameErrors()`), so one throw doesn't freeze the app.
- `npm run smoke` also covers reload, junk query values, Android phone emulation and a memory soak (`SOAK_S`, default 120; `SOAK_S=0` skips it).
- SwiftShader runs every page of a headless browser in one GPU process: a page left rendering a grown tree starves the next page (navigations take 60 s+, `page.goto` times out). Close pages you are done with; smoke runs each phone step in a fresh context.
- Telemetry: `public/telemetry.js` (classic, loads before the bundle) + `src/tel.ts` wrapper (`tel.phase`, `tel.log`, `tel.setStats`). Wrap new risky steps in `tel.phase('name')`; per-frame phases pass `frequent=true`. See README "Telemetry and diagnostics".
- Diagnostics switches live in `diagSwitches` (`src/tel.ts`); keep `public/diag.html` links in sync.
- Leaf render modes (`LeafMode` in `src/render/leaves.ts`): 'full' (Standard + onBeforeCompile, DoubleSide, shadows, GPU wind), 'safe' (Lambert, no shader patch, FrontSide doubled geometry, instance colours, no shadows, no wind; geometry/map/vertexColors/emissive per `LEAF_VARIANTS` V0..V4), 'basic' (unlit). Safe is automatic on PowerVR/Imagination, mobile Low and after a context loss in the tab (`pickLeafMode` in `main.ts`); `?leafsafe=1/0`, `?leafshader=basic|safe|full`, `?leafshadow=0/1`. Context losses are counted in `sessionStorage['arbor.ctxLost']`: 1st → reload with safe leaves + no shadows, 2nd → no reload, safe-mode links page. diag.html clears the counter; `/diag` serves it.
- Camera: only a real drag (>8 px) or wheel disables autoFrame (a tap used to freeze the camera at sapling distance). Portrait framing fits the crown circle to the horizontal FOV (`Stage.frame`); landscape keeps the sphere fit.
- Low quality: tight light-space shadow frustum + larger bias, warm bark tint (main.ts). High keeps the old values.
- Debug HUD line is hidden by default: `?hud=1` or D. `node scripts/phoneshots.mjs [stages] [query] [prefix]` renders Android-emulated 411x777 framed + trunk close-up shots.
- Leaf variants (`LEAF_VARIANTS` in `src/render/leaves.ts`): V0 = 1d88059 known-good (doubled card + uv + leaf map + alphaTest 0.5, no vertexColors, emissive black) is the hard-pinned default for every safe/basic leaf path (PowerVR/Imagination, mobile Low, after a context loss). V4 (polygon, vertexColors+emissive, no map/uv) killed the PowerVR D-Series context on the first leaf frame. `?leafvariant=N` is a manual dev override only (diag.html warns V1–V4 may crash the GPU). There is no automatic BAD marking and no on-device variant ladder: a crashing variant resets the GPU for all tabs and Chrome then blocks WebGL for the site; a background tab's context loss falsely marked V0 bad. `main.ts` deletes stale `localStorage['arbor.leafBad.*']` / `arbor.ladder` keys on load. `node scripts/leafvariants.mjs '' leafvariant=0 ...` renders variants in headless phone emulation (404s are POST /log on vite: ignore).
- Context losses while `document.visibilityState === 'hidden'` are logged (`ctx_loss_hidden`) but do not count toward the crash guard or change modes; the page reloads as-is once visible after restore (`Stage` constructor).
- WebGL renderer creation failure (Chrome blocks WebGL after a GPU reset) shows a full-page "3D graphics are blocked" message (`#nowebgl`, telemetry `webgl_create_failed`) and stops `main.ts` via a never-resolving top-level await.
- Safe leaf map is `cleanLeafTexture` (alpha exactly 0/1, RGB dilated with the leaf colour, hand-built mips re-thresholded at 0.5): the premultiplied canvas map had black RGB under transparency and GPU mips whose alpha averaged to ~0.5 over the card. `?leafmap=raw` restores the old map for comparison. Ghost cards did not reproduce on SwiftShader with either map. Renderer is explicitly `alpha: false`.
- Leaf lighting is CPU-baked into instance colours (`Leaves.update`, inputs via `Leaves.setLighting` from `main.ts` each leaf rebuild). Safe path: colour = albedo/mapMean × E_wanted/E_lambert per channel (E_wanted = hemi·occlusion + sun·|n·L|·sunVis + translucency glow when the sun is behind the leaf from the camera; E_lambert = what the Lambert shader will add), clamped to 8. Full path bakes only albedo × occlusion (its shader does sun/shadow/translucency). Sun visibility = per-voxel march through `TreeSim.lightGrid` (stored by `updateLight`, `lightVersion` bumps) toward the sun.
- Leaves come in 8-leaf clumps per leafy node: 4 from the sim rng + 4 smaller tip leaves from a per-node hash (does not consume the sim rng: tree shapes are unchanged). Oak default size 0.145, density 3.4. Render-side shell fill: each sim leaf on a lit node (`nd.light` 0.06→0.4) gets up to one hashed extra copy (≈ 8 → 13 per outer clump, interior stays sparse); leaves scale up to 1.5x with camera distance (0.9H→2.6H, H = crown height) so the far silhouette fills; `main.ts` rebakes when the camera distance changes > 25% (≤ 1/s). Low caps drawn leaves at 32k (`Leaves.maxInstances`, rank thinning); oak at t90 ≈ 30k phone / 33.6k desktop. No leaves on segments pointing steeply down (`wdy < -0.75`).
- Leaf map: `makeLeafTexture` (textures.ts) paints a 512 px oak leaf procedurally (lobed asymmetric outline + teeth, base→tip gradient, tapering lighter veins, blotches/speckles, dark margin, baked sheen) in real albedo colours; instance colours divide by its mean (`mapMeanColor`), so retuning colours does not shift the lighting bake. Safe path still goes through `cleanLeafTexture`.
- Canopy shadow (`src/render/canopyShadow.ts`): whenever leaves don't cast shadow-map shadows (safe path), a CPU-baked 256² canvas is drawn as a transparent MeshBasicMaterial ground plane, and branches stop casting. The bake is deposit-then-blur in a sun-aligned frame (texture u = sun azimuth, w = perpendicular, independent texel sizes; the plane is rotated about y to the azimuth and scaled to the footprint): each leafy node and each sample along order ≤ 1 limbs is projected along the sun and deposited bilinearly into two of 5 blur-level layers on a 128² blur grid picked by its penumbra sigma (own radius + 0.035 × height / sun elevation), then the layers are cascaded widest-first with one fractional-box sliding pass per axis and level (sigma × stretch along u) and upsampled to 256², followed by the trunk contact ring, elliptical sun flecks, world-anchored dapple noise and the opacity map (0.3 low sun → 0.55 noon). Cost is a fixed 10 passes over 128² plus one opacity pass over 256², independent of sun height (do not go back to per-caster gaussian splats: that was 700 ms at 4x throttle). `canopy.lastMs/maxMs/bakes` hold bake timings. Rebuilds when the sun moves or the light grid changes (≥ 2 s while growing). PowerVR rule: safe-path changes stay data-only (instance colours/matrices, texture pixels, plane transform, intensities, castShadow); no new leaf material flags/programs.
- GTAO renders its normal/depth g-buffer with `scene.overrideMaterial` (no map/alphaTest). Alpha-cut objects must set `userData.gbufferMaterial` (allowOverride=false), which `Post` swaps in for that pass. Leaves do this; otherwise whole quads show up close. `node scripts/closeup.mjs [prefix] [hours] [query] [dist]` takes close-up crown shots (NOAO=1 turns GTAO off).
- Controls panel rules: every control writes through `Automation.userSet(path, value)` (hand-set value wins: path leaves all journey keyframes, its drift goes off). Never write `params.x = v` from UI code for automatable params, or a journey/drift overwrites it on the next sim step (that was the "values reset" bug). Controls are declared as data (`TREE`, `SKY`, `ADVANCED` in `ui.ts`); add a section with one `tab(...)` call. Stable hooks for scripts: `[data-tab]`, `.ap-chip[data-preset]`, `input[data-param="group.field"]`, `[data-drift]`, `[data-colour]`, `#arbor-panel(-open|-close)`, `#arbor-pause`, `#arbor-new`, `#arbor-regrow`, `#arbor-surprise`, `#arbor-add-keyframe`, `#arbor-clear-journey`, `#arbor-journey-info`. `?panel=open|closed`, `?tab=`. No `backdrop-filter` on the panel (blurring the canvas costs the phone GPU). H/C/D work while a slider, switch or button has focus (`typing()` in `main.ts`).
- `SMOKE_GPU=vulkan` runs smoke on the real GPU (under 2 min). Use it when the host is loaded: on SwiftShader frames then take seconds and panel clicks time out with "waiting for element to be stable" (0 FAIL, not an app bug).
- Smoke on a vite dev server fails its console-error checks (POST /log 404s). Run it against the built app: `npm run build && HOST=127.0.0.1 PORT=5301 node server/serve.mjs`, then `SOAK_S=0 node scripts/smoke.mjs http://127.0.0.1:5301/`. `PORT=5300 node scripts/panelshots.mjs` takes the panel screenshots.
- Meadow (`src/render/meadow.ts`, WP3): grass tufts + 4 wildflower species as 32 `InstancedMesh` patches (24 grass wind-phase patches, 2 per flower species) inside one `Group` (`main.ts` sweeps the scene's direct InstancedMesh children on leaf realloc, so never add them to the scene directly). PowerVR rule: each material is `leafMaterial.clone()` with only `map` swapped (maps through `cleanLeafTexture`), geometry = 3 crossed doubled cards with position/normal(up)/uv, instanceColor, no shadows; smoke asserts the phone program count equals `?meadow=0` at noon and night (9). Motion = per-patch shear object matrix from `wind.gustAlong(phase)` each frame, zero buffer uploads. Shade is a field, not a per-tuft march: when the sun direction (2 decimals) or (≤ every 3 s) the light grid changes, `fillShade` marches `sim.lightGrid` straight up and toward the sun on a 112² grid over ±27 m (only the cell rectangle the crown can shade), blurs it 1-4-6-4-1 per axis into the live field and dirties all patches; tufts sample it bilinearly (up = shorter/sparser plants, toward the sun = darker), which gives a soft gradient instead of dark squares. Field rows, the two blur stages and the patch rebakes (also triggered by light colours, night, tint, trunk radius, draw fraction) share `FRAME_BUDGET_MS = 1` per frame (`stats.sliceMaxMs`; patches wait while a fill is in flight); `bakeAll` finishes everything at once. Colour gains are tuned against the ground in screenshots (less straw and darker toward the rim so lone tufts match the ground), low sun adds an upright-blade term. Placement: 30 % of tufts in a core with density exp(-r/6), 70 % even over the disc, thinning from r 16 to `R_FAR` 26 so a portrait frame's foreground is covered. Tuft map: bottom rows cut into a ragged root line (alpha 0/1) and the lowest fifth faded to the mean tuft colour, card sunk 3 % (no base line). 26k tufts / 2600 flowers generated; Low draws 45 % (11.7k / 1174), 22 % once the adaptive pixel ratio stepped below 1.5. Patches are assigned by distance along the wind at construction: changing `wind.dirX/dirZ` later needs a re-sort. `?meadow=0`, `params.sky.meadow`, `__arbor.meadow.counts/stats`. On High each mesh has a `userData.gbufferMaterial` for GTAO. `node scripts/meadowshots.mjs [hour]` = trunk-base shot + 0.5 s motion diff; `SHOT_PREFIX` env on `auditshots.mjs`.
- Wind (`src/wind.ts`, no three import): the single wind source, `wind.update(dt, params.sky.wind, night)` once per frame in `main.ts` (`meadowFrame`), `wind.gust(x, z)` / `gustAlong(d)` travelling wave. Later packages (leaf wind, falling leaves, storms) read this, never their own clock.
- Weather (WP9; `src/weather.ts`, no three import; shared instance `weather`): state machine calm → breeze → front → rain → clearing, `weather.update(dt, params.weather.event, params.weather.lightning)` once per frame in `main.ts` (`weatherFrame`, before `stage.frame`). Outputs, all exactly 0 in settled calm (they snap within 0.002 of the target): `wind` 0..1 (storm share of the wind, leads the rain), `cloud`, `rain`, `flash` (0 when lightning is off), `bolt {on, variant, u, dist}`, `phase`, `storming`, and `violence` (= `wind`): the one "how violent is it right now" scalar the breakage package should read. `onStrike(dist)` is the thunder hook (nothing listens yet; no `src/audio.ts`). `trigger()` = one full sequence ("Storm now"), `snapStorm()` = jump to the full storm (`?weather=storm`), `strike()`, `holdFlash` (test hook). Auto schedule: 240 to 660 s between storms; shot scripts that run for minutes should pass `weather=calm`. `params.weather` is excluded from `paramsSignature` and from preset loads.
- Wind interface for later packages (`src/wind.ts`): `wind.update(dt, params.sky.wind, night, weather.wind)`; `wind.base` (strength 0..1 this frame: calm setting, lifted toward `Wind.STORM_BASE = 1` by the storm, never lowered), `wind.storm`, `wind.dirX/dirZ`, `wind.gust(x, z)` (strength at a point incl. travelling gust), `wind.speedAt(x, z)` and `wind.velocityAt(x, z, out)` in m/s (`Wind.speed(s) = 2 + 20 s²`: about 4.5 m/s at the calm 0.35, 22 m/s in a storm gust). The storm also runs the gust clock up to 2.6x faster. Direction does not change in a storm (meadow patches are sorted along it).
- Storm look is drift-free by construction: `Stage.frame` recomputes every calm value each frame and `Stage.applyWeather` (end of `frame`) only multiplies/lerps on top from `stage.wx.cloud` (sky `cloudCoverage/cloudDensity` 0.35 → 0.95, `skyGain` x 0.28, sky tint toward grey, sun discs and stars x (1 − cloud), fog colour toward dark grey-blue and density x 2.2, sun x 0.22 and cooler, hemisphere cooler x 0.7, env x 0.45); `Stage.applyFlash` (called by `weatherRender` right before `render`, after every bake has read the lights) adds the flash, scaled by 1 / night exposure. Anything new the storm changes must follow the same rule (derive from the calm value every frame; never accumulate). `main.ts` raises `leavesDirty` when `cloud` moved by 0.06 or settled (safe leaf path bakes the light), and fades the canopy decal (`opacity = 1 − 0.65 cloud`).
- Rain and bolt (`src/render/rain.ts`): P-DECAL only: `canopy.mesh.material.clone()` with `map`, `color`, `opacity`, `blending` changed; three camera-facing streak sheets (16 m / 6 m / 2.2 m; `texture.offset` scroll, plane rolled by the wind slant; 2 sheets once the adaptive pixel ratio stepped below 1.5) + one additive bolt plane at 110 m (nearer than the audit's 300 to 800 m because the clone keeps `fog: true` and storm fog would erase it; `bolt.dist` still carries 300 to 800 m for thunder). The planes carry an invisible `userData.gbufferMaterial` so GTAO ignores them. Program count in phone emulation is identical with and without the storm (smoke gate; `scripts/wxprograms.mjs` lists the cache keys). Note: on Low one more program (bark, different flags) appears a few seconds after an hour change in calm weather too; compare counts at equal times.
- Breakage (WP10; `TreeSim.breakAt/windLoad/loadRatios` in `src/sim/tree.ts`, `src/render/debris.ts`, `breakagePre/breakagePost` in `main.ts`). `breakAt(id)` resolves to the node's chain and breaks at the chain base: a chain of ≥ 4 nodes keeps `[branch point, first node]` as a stub (alive = false) and the rest moves to a NEW pruned chain appended to `sim.chains` (so `node.chain` stays valid and chains can now start mid-limb); every chain whose `nodes[1]` is in the subtree is pruned, buds on detached nodes are dropped, `topology++`, `lightTimer = 0`, and a `BreakEvent {root, nodeIds, chains, time, leaves, radius}` goes to `sim.breaks`. Detached nodes stay in `sim.nodes` (ids are stable); nothing is removed. Frame order matters: `breakagePre` (rule; `updateStructure(0)` on a paused tree) → `redraw` (branch mesh drops the limb, leaf follow) → `breakagePost` (debris spawn, then `leavesDirty` + `leafRestart` so an open leaf pass, which still holds the detached leaves, is restarted). `Leaves.takeInstances(inSub)` copies the drawn matrices/colours of the subtree and hides them in the live mesh (zero matrix, record node id −1, which `place`/`follow` skip); it must run after `follow` in the frame because `follow` clears the matrix update ranges. Debris, PowerVR rule: limb wood = a second `BranchMesh` constructed with the LIVE bark material instance (constructor accepts a material) fed a fake sim of the detached chains; limb leaves = `InstancedMesh(live leaf geometry, live leaf material)` with instanceColor; both in a `Group` under `debris.group` (never the scene directly); bounding spheres are preset. Motion is one rigid transform per limb: hinge about the stub end (α = 1.5 g sin θ / L + wind torque, until 50° or 0.9 s), free flight (gravity, drag toward the wind velocity scaled by leaves per node), impulse contacts on 16 farthest-point samples (restitution 0.15, friction 0.7), rest, leaves brown over 60 s (colour upload ≤ 2 Hz), max 3 limbs (older scale to 0 and are disposed). Subtrees under `TWIG_NODES` 12 nodes spawn falling leaves only (per-instance matrices while falling, removed 24 s after landing). Rule: 4 Hz, only while `wind.base > 0.6`; `u = (gust²·(A_LEAF·subLeaf + subLen·2r)·d⊥wind + G_W·subW·d_horizontal) / (strength·SIGMA_REF·r³)`; `damage += dt·max(0, u−1)`, break at > 1, one break per evaluation. `SIGMA_REF` 9.94e6 was set as the 98th percentile of u at gust 1.0 on the t = 90 default oak (then: 120 s at `wind.base` 1.0 → 4 twigs + 1 small limb, 0.8 → 3 + 1, ≤ 0.6 → 0); since the sag/downward-growth change the same value sits at p98 = 0.94 and gives 1.0 → 5 twigs + 0 limbs, 0.8 → 1 + 0, ≤ 0.6 → 0 (inside the tolerance, not recalibrated). Recalibrate with `scripts/breakcalib.mjs` when leaf counts, radii or `Wind.gust` change. Program gate: smoke asserts the phone program count is equal before / in flight / at rest (10). Read program counts only after the page has settled about 6 s: the live bark program is first compiled while the branch geometry is still empty and three re-keys it (position + normal attributes) by itself a few seconds later, which looks like "+1 program" at whatever happens then.
- Wind sway (`src/render/sway.ts`, no three import; `sway` in `main.ts`, `params.sway.amount`, Sky tab "Branch sway", `?sway=0`). Render-side only: `Sway.update(sim, wind, amount)` derives an offset per node id (`Sway.D`, 3 floats) from the REST pose (`TreeNode.w*`), `wind` and `wind.t` every time; nothing accumulates and the sim fields are never written, so `windLoad`, the light grid, canopy shadow, meadow shade and debris spawn keep reading rest geometry and zero wind / amount 0 is exactly the rest pose (`D` all 0, leaf translations bit-equal to their rest translations; smoke checks it). Model = bend cascade: one force vector per chain (downwind lean ∝ gust^2.5 from `wind.gustAlong` at the chain base 0.35 s behind the front, plus an own-phase oscillation ∝ gust^1.25 along / across / vertical, faster on thinner wood, per-chain hash phase), each segment adds the rotation `(s × F) · FLEX / r^1.5` (cap `FLEX_MAX` per metre, `TH_MAX` 0.6 rad total) to its parent's, offset = parent offset + rotated segment − rest segment (renormalised to the rest length), clamped to `D_MAX` 1.3 m. Child chains start from their branch point's rotation and offset, so junctions cannot tear; pruned chains (also detached limbs) get 0; chains of ≤ 2 nodes (break stubs) add no bend of their own and ride their parent. Rest data (segment, flex, chain per node) is cached while `sim.time`/`topology`/node count are unchanged. Drawing, same on both qualities, data-only (PowerVR rule: position attribute and instance matrices of the existing meshes, no new mesh, material or program; smoke asserts the phone program count equals `?sway=0` in calm and storm): `BranchMesh.applyOffsets(D)` writes position = rest position (kept from the last full `update`) + offset of the vertex's node (per-ring translation; normals/uvs/index untouched, one position upload), `Leaves.sway(D, P)` writes translation = rest translation (`restT`, recorded by `place` for drawn matrices) + offset interpolated parent → node by the leaf's `t` (translation only, one whole `instanceMatrix` upload). A full branch rebuild with offsets per frame was measured and rejected (+13 ms JS at 4x throttle on the phone path, +8 ms on desktop High). Scheduling in `redraw`: offsets are recomputed when the branch mesh is due (High every frame, Low every second frame), wood and leaves are written in the same frame; `Leaves.sway` also runs after a frame in which the pass or follow placed leaves (they write rest translations). `Leaves.follow` / `markMoved` still see the rest pose, so the "skip nodes at rest" shortcut keeps working. Rules for later packages: read `sway.D` (+ `sway.P`) if something must ride a twig (falling-leaf spawn points, birds); anything that writes leaf matrices must go through `place` or write `restT` too; `takeInstances` hands the REST translation to the debris (the debris wood is built from rest), so a limb jumps from its swayed to its rest pose in the frame it breaks; the canopy decal and meadow shade stay static under the moving crown (no rebake); normals of swayed wood are the rest normals. Tuning constants are at the bottom of `sway.ts`; `node scripts/swayshots.mjs` (MODES, WX, THROTTLE, SHOTS) reports cost with/without sway, peak offsets, programs, the rest check and takes frame bursts. (The whips that used to hit `D_MAX` are gone, see "Sag and downward growth".)
- Falling leaves (`src/render/leaffall.ts`, `leafFallFrame` in `main.ts` after `breakagePost`; `?leaffall=0`, `params.leaffall {enabled, rate, litter}`, `__arbor.leafFall` with `force(n, storm)`, `stats`, `state`, `clear()`). The one falling-leaf system: calm let-go, storm tear-off, litter, and the breakage twig leaves (`Debris.leafSink` hands `takeInstances` output to `LeafFall.adopt`; the old per-twig mesh path in `debris.ts` only runs when no sink is set, e.g. `?leaffall=0`). PowerVR rule: two `InstancedMesh`es (air 512 slots, litter 2400 slots) built from the LIVE leaf geometry and LIVE leaf material instance, in one `Group`, instance matrices and colours only; smoke asserts the phone program count equals `?leaffall=0` in calm and in a storm (10 = 10), desktop High storm is 32 with and without. A leaf starts as a copy of a drawn crown instance (`Leaves.sampleInstance(u, m, c)`: world matrix and baked colour at that moment; the only thing read from the crown, no instance index is kept) and the crown instance is NOT removed (a 120 s storm tears about 3200 of 48k on High; the leaf pass redraws anyway). Spawn rate = maturity (sim leaves 500 to 3000) x [calm (0.04 + 0.5 gr³) x (base/0.35)² x (1 + 2 dusk) + `weather.violence` x (Low 40 / High 110 per s) x (0.06 + gr³)], gr = `wind.gust` at the crown / `wind.base`; in a storm the best of 4 sampled candidates by "windward + outer + high" is taken. Flight: horizontal velocity relaxes (0.4 s) to `Wind.speed(gust at the leaf)` x sail (calm 0.22 to 0.42, storm up to 0.82) x shelter (0.3 at the ground to 1 at 60 % crown height) plus a sideways flutter; vertical to minus the fall speed (0.7 to 1.3 m/s calm, up to 3 in a storm) plus a decaying lift (45 % of storm leaves, 2 to 6.5 m/s) and gust turbulence; tumble about a per-leaf axis, faster with speed. Touch-down at 0.32 m: 0.3 s blend to a lying pose (random heading, tilt up to 26 degrees, rest height 0.06 to 0.3 m, i.e. caught in the grass: a leaf flat on the soil is hidden by the 0.3 m tufts), then it moves to the litter ring. Litter: oldest-first recycle at the cap, browns over 120 s (quantised, per-slot ranged colour upload), round-robin scan every 0.7 s; half of the slots (hash) can be lifted into a short hop by a gust > 0.72 (same air system, so nothing slides or pops); beyond 42 m it is dropped. Caps (air / litter): High 320 / 2000, Low 110 / 600, halved with the storm rate once the adaptive pixel ratio stepped below 1.5. Colour: the baked crown colour is pulled into [0.9, 1.3] x the running mean luminance over the first second of flight (safe-path colours compensate the Lambert term of the crown orientation, up to 8x, and glowed white once the leaf turned; interior leaves carry occlusion). Uploads: air = one range [0, n) per frame, litter = touched slots only. Cost at 4x CPU throttle in phone emulation (`stats.sumMs / frames`): calm 0.10 ms, storm 0.33 ms mean per frame (the `tel.phase` profile floor is about 0.6 ms per phase at 4x, so read the stats, not the profile). Uses its own xorshift; the sim rng is untouched. On the full path the leaf shader's GPU wind also moves litter slightly. `node scripts/leaffallshots.mjs URL phone|desk` (calm forced leaf, gust-peak storm pair, ground after STORM_S), `node scripts/leaffallcount.mjs URL phone|desk calm|storm 120` (THROTTLE=4 for the cost).
- Sag and downward growth (`SAG_RIGHT`, `DOWN_MAX` in `src/sim/tree.ts`). The oak used to carry bare, vertical strands from the crown to the ground (t = 90: 28 chains, 190 nodes more than 2 m below their chain base, 521 leafless `wdy < -0.75` segments, 144 nodes at the 1.3 rad sag cap, lowest node 1.5 m below ground; none at t = 30, all there by t = 60). Two causes, two rules. (1) `updateStructure` summed sag down the whole path (`parent.sag + bend`), and an unbranched shoot keeps twig radius however long (the pipe model sees one tip), so metres of wood sat at the per-node bend cap and everything downstream turned vertical, while growth, which runs in rest space, still saw the shoot inside the crown and kept extending it. Now inherited sag fades: `sag = parent.sag * exp(-len * (1 - min(1, weeping)) / SAG_RIGHT) + bend`, `SAG_RIGHT` 3 m (new wood rights itself; droop stays local to the loaded stretch). (2) Attractors below a high branch pulled order 1 shoots straight down for metres in rest space too: `completeSegment` limits the wanted direction to `dy >= -DOWN_MAX` (0.3), applied before the `maxTurn` slerp so a steep bud levels out smoothly. `growth.weeping >= 1` switches both rules off (the willow preset is bit-identical to before, including its own hanging bare strands and nodes below ground; weeping 0.7 keeps 30 %). After: 0 nodes at the cap, 12 steep segments, all above 3.7 m inside the crown, nothing below 1.9 m. `node scripts/strands.mjs URL [times] [query]` prints the census (ROWS = chains listed), `node scripts/strandshots.mjs URL prefix [query]` takes fixed-camera wide/under/side shots (MODES, TIMES). Any change here moves radii and leaf counts: rerun `scripts/breakcalib.mjs` (after this change p98 = 0.94, 120 s at 1.0 → 5 twigs + 0 limbs, 0.8 → 1 + 0, ≤ 0.6 → 0; `SIGMA_REF` left at 9.94e6).
