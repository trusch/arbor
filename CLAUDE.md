# Arbor: project notes

- Stack: Vite + TS + three r187 + lil-gui. Local git only, no remote. Repo has `commit.gpgsign=false` locally.
- All tunables live in `src/params.ts` (`ArborParams`); sim/render read them live. Add new params there and in `src/ui.ts`.
- Sim is three-free (`src/sim/`); renderer reads `TreeNode.w*` (sagged world) fields.
- Children always have larger node ids than parents; `updateStructure` relies on this for its bottom-up and top-down passes.
- three r187 removed PCFSoftShadowMap; use PCFShadowMap + `shadow.radius`.
- Verify visually: `npm run shots`, then look at the PNGs in `shots/`.
- Look/lighting is driven by `params.sky` (timeOfDay, cycle, dayLength, latitude, sunYaw, exposure, fog, godRays, quality). `params.light` is only the phototropism direction for the sim.
- Preetham sky values blow up bloom at low sun: keep the sky clamp in `atmosphere.ts` (`patchSky`) unless you also retune bloom.
- `scripts/screenshot.mjs` args: stages, extraQuery, prefix, `hour:name,...` list (or `none`). SHOT_W/SHOT_H env set the resolution. Each run takes about 70s on SwiftShader.
- Chains can be `pruned` (shaded out by the light grid in `TreeSim.updateLight`). Renderers must skip pruned chains, and the pipe model ignores them. Radii never shrink.
- `BranchMesh.update` is throttled in `main.ts` (`redraw`). Call it with `meshAge = Infinity` to force a rebuild (see `fastForward`).
- Automation (`src/automation.ts`) writes into the live params object before every sim step; presets are copied into params in place (`loadPreset` in `main.ts`) so GUI controllers stay bound. Use `?preset=Name`.
- Sun discs are drawn in the patched sky shader (`disc1*/disc2*` uniforms); do not use sprites (GTAO override material renders them as solid quads). The env-map sky has `discOn = 0`.
- Screenshot script disables cinema (`cinema=false`) and accepts `PORT` env so several runs can go in parallel (more than ~4 in parallel times out).
- Deploy: `npm run deploy` (build + `systemctl --user restart arbor`). Unit `~/.config/systemd/user/arbor.service` (copy in `deploy/`) runs `server/serve.mjs` on 10.77.0.2:8050 (VPN): static `dist/` + `POST /log` → `logs/client.jsonl`. HTML is served `no-store`. Vite `base: './'`. Ports 8010–8040 belong to other apps.
- `npm run smoke` (scripts/smoke.mjs) drives the app in headless chromium; run it after interaction changes.
- Mobile/low-end (UA mobile, touch + small screen, deviceMemory < 4) defaults to `quality=Low` and `maxNodes ≤ 7000` (`lowEndDevice` in `main.ts`); `?quality=High` overrides. Pixel ratio is adaptive (`Stage.adaptDpr`): starts at min(devicePixelRatio, Low 2 / High 1.5), 3 s fps windows (first 3 s, hidden-tab and >2 s-gap windows ignored), < 40 fps steps down 2→1.75→1.5→1.25→1, > 57 fps for 10 s steps up (never above start, blocked 30 s after a step-down); `?dpr=N` pins it; telemetry `dpr_change` {from,to,fps} + `pixelRatio` in hb stats. 1024 shadow map on Low (`Stage.applyQuality`). Renderer is antialias:true on every quality (`?antialias=0` diag only). `SHOT_DPR=2.625 node scripts/phoneshots.mjs` emulates the real phone DPR. `Stage.post` is lazy: never touch it on Low or it allocates the GTAO/bloom render targets.
- Context loss shows a notice and reloads on restore; the rAF loop wraps each frame in try/catch (`__arbor.frameErrors()`), so one throw doesn't freeze the app.
- `npm run smoke` also covers reload, junk query values, Android phone emulation and a memory soak (`SOAK_S`, default 120; `SOAK_S=0` skips it).
- Telemetry: `public/telemetry.js` (classic, loads before the bundle) + `src/tel.ts` wrapper (`tel.phase`, `tel.log`, `tel.setStats`). Wrap new risky steps in `tel.phase('name')`; per-frame phases pass `frequent=true`. See README "Telemetry and diagnostics".
- Diagnostics switches live in `diagSwitches` (`src/tel.ts`); keep `public/diag.html` links in sync.
- Leaf render modes (`LeafMode` in `src/render/leaves.ts`): 'full' (Standard + onBeforeCompile, DoubleSide, shadows, GPU wind), 'safe' (Lambert, no shader patch, FrontSide doubled geometry, instance colours, no shadows, no wind; geometry/map/vertexColors/emissive per `LEAF_VARIANTS` V0..V4), 'basic' (unlit). Safe is automatic on PowerVR/Imagination, mobile Low and after a context loss in the tab (`pickLeafMode` in `main.ts`); `?leafsafe=1/0`, `?leafshader=basic|safe|full`, `?leafshadow=0/1`. Context losses are counted in `sessionStorage['arbor.ctxLost']`: 1st → reload with safe leaves + no shadows, 2nd → no reload, safe-mode links page. diag.html clears the counter; `/diag` serves it.
- Camera: only a real drag (>8 px) or wheel disables autoFrame (a tap used to freeze the camera at sapling distance). Portrait framing fits the crown circle to the horizontal FOV (`Stage.frame`); landscape keeps the sphere fit.
- Low quality: tight light-space shadow frustum + larger bias, warm bark tint (main.ts). High keeps the old values.
- Debug HUD line is hidden by default: `?hud=1` or D. `node scripts/phoneshots.mjs [stages] [query] [prefix]` renders Android-emulated 411x777 framed + trunk close-up shots.
- Leaf variants (`LEAF_VARIANTS` in `src/render/leaves.ts`): V0 = 1d88059 known-good (doubled card + uv + leaf map + alphaTest 0.5, no vertexColors, emissive black) is the hard-pinned default for every safe/basic leaf path (PowerVR/Imagination, mobile Low, after a context loss). V4 (polygon, vertexColors+emissive, no map/uv) killed the PowerVR D-Series context on the first leaf frame. `?leafvariant=N` is a manual dev override only (diag.html warns V1–V4 may crash the GPU). There is no automatic BAD marking and no on-device variant ladder: a crashing variant resets the GPU for all tabs and Chrome then blocks WebGL for the site; a background tab's context loss falsely marked V0 bad. `main.ts` deletes stale `localStorage['arbor.leafBad.*']` / `arbor.ladder` keys on load. `node scripts/leafvariants.mjs '' leafvariant=0 ...` renders variants in headless phone emulation (404s are POST /log on vite: ignore).
- Context losses while `document.visibilityState === 'hidden'` are logged (`ctx_loss_hidden`) but do not count toward the crash guard or change modes; the page reloads as-is once visible after restore (`Stage` constructor).
- WebGL renderer creation failure (Chrome blocks WebGL after a GPU reset) shows a full-page "3D graphics are blocked" message (`#nowebgl`, telemetry `webgl_create_failed`) and stops `main.ts` via a never-resolving top-level await.
- Safe leaf map is `cleanLeafTexture` (alpha exactly 0/1, RGB dilated with the leaf colour, hand-built mips re-thresholded at 0.5): the premultiplied canvas map had black RGB under transparency and GPU mips whose alpha averaged to ~0.5 over the card. `?leafmap=raw` restores the old map for comparison. Ghost cards did not reproduce on SwiftShader with either map. Renderer is explicitly `alpha: false`.
- Leaf lighting is CPU-baked into instance colours (`Leaves.update`, inputs via `Leaves.setLighting` from `main.ts` each leaf rebuild). Safe path: colour = albedo/mapMean × E_wanted/E_lambert per channel (E_wanted = hemi·occlusion + sun·|n·L|·sunVis + translucency glow when the sun is behind the leaf from the camera; E_lambert = what the Lambert shader will add), clamped to 8. Full path bakes only albedo × occlusion (its shader does sun/shadow/translucency). Sun visibility = per-voxel march through `TreeSim.lightGrid` (stored by `updateLight`, `lightVersion` bumps) toward the sun.
- Leaves come in 8-leaf clumps per leafy node: 4 from the sim rng + 4 smaller tip leaves from a per-node hash (does not consume the sim rng: tree shapes are unchanged). Oak default size 0.145, density 3.4. Low caps drawn leaves at 25k (`Leaves.maxInstances`, rank thinning). No leaves on segments pointing steeply down (`wdy < -0.75`).
- Canopy shadow (`src/render/canopyShadow.ts`): whenever leaves don't cast shadow-map shadows (safe path), a CPU-baked 256² canvas (light-grid density + order ≤ 1 limbs projected along the sun, blurred, noise-dappled) is drawn as a transparent MeshBasicMaterial ground plane, and branches stop casting. Rebuilds when the sun moves or the light grid changes (≥ 2 s while growing). PowerVR rule: safe-path changes stay data-only (instance colours/matrices, texture pixels, intensities, castShadow); no new leaf material flags/programs.
